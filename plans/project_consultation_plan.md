# 青空文庫の著者識別に向けた実験設計・システム構想・分担計画案

> [!WARNING]
> 本文書は初期の構想記録．現行仕様は `plans/research-context.md` と各チケットが正．以下の記述は 2026-11-16 の講義資料照合で訂正済み．
> - 重み付き Jaccard / Dice（ $\sum \min / \sum \max$ ）は講義資料に存在しない．講義の Jaccard は「単語の重なり率」（第 2 回 p.45），Dice は第 5 回 p.26 で名称のみ．類似度はコサインに統一し，Jaccard / Dice は不採用．
> - A の Z-score 標準化は採用せず，全次元を相対頻度にそろえる（002）．
> - D の「第 3 回の単語分散表現の平均（SIF 等）」は不採用．LSI のみ（005）．
> - 重心法の根拠は第 2 回 p.48「各カテゴリを代表する文書との類似度が最大のカテゴリへ分類」．$k$-NN（ $k > 1$ ）は講義外．

## 実験設計における方法論的リスクと盲点の批判的レビュー

- **トピック漏洩（Topic / Content Leakage）の排除**
  - 同一作品内でのデータ分割（Train / Test 混在）の禁止．特定作品の固有名詞（例：「山嵐」「清」）や題材への過学習を防ぎ，純粋な「文体（Stylometry）」を評価するための**作品単位での分割（Leave-One-Work-Out 等）**の徹底．
- **情報漏洩（Data Leakage）の防止**
  - TF-IDF 等の語彙集合（Vocabulary）および IDF 統計量，正規化パラメータ（平均・標準偏差）の算出を登録用（Train）データのみに限定．評価用（Test）データを一切含めないパイプラインの構築．
- **サンプルコーパス（AozoraCorpus）の制約と実験プロトコル**
  - サンプルコーパス内の 30 作品では，複数作品が収録されている作家が**夏目漱石（3 作品：『坊っちゃん』『こころ』『三四郎』），太宰治（2 作品：『惜別』『斜陽』），寺田寅彦（2 作品：『映画芸術』『柿の種』），田山花袋（2 作品：『蒲団』『田舎教師』）のちょうど 4 人（計 9 作品）**．
  - サンプルコーパスのみで完結させる場合，この 4 人を対象作家に設定．ただし「チャンク数が多いからサンプル数に困らない」という誤解（擬似反復：Pseudoreplication）を避けるため，**「同一作品内分割（Intra-work Split：トピック漏洩あり）」と「作品単位分割（Inter-work / Leave-One-Work-Out Split：純粋な文体評価）」の両方を比較実験**し，単語 TF-IDF が別作品で精度低下する一方，文体・機能語特徴が頑健であることを実証する設計を採用．
  - **仮名遣い・文語体の交絡対策**：上記 4 人（漱石・太宰・寅彦・花袋）はいずれも明治後期〜昭和初期の口語体（言文一致体）であり，青空文庫では原則として新字新仮名版が流通（実データの表記確認は必須）．万が一旧仮名遣いが混在する場合，文字 N-gram（A）や MeCab の形態素解析精度（B）にも直撃するため，MeCab UniDic 等の利用や「基本形・発音・品詞」の抽出で表記揺れを吸収．
- **課題 2（文・文章の類似度計算）の規約遵守**
  - 第 3 回講義資料の注意事項に基づき，外部ライブラリの類似度計算関数や分類器の直接利用を禁止．前処理としての形態素解析器（MeCab 等）の利用にとどめ，特徴量ベクトル化および類似度算出ロジックをフルスクラッチで実装．

## 文章類似度の計算手法と特徴量設計（アブレーション計画）

### 観点別の特徴量設計（文体 vs 内容の切り分け）

- **A. 表層・文字種・句読点特徴（計量文献学的文体特徴）**
  - 文字 N-gram（Bi-gram / Tri-gram）：送り仮名や仮名遣いの癖の捕捉．
  - 句読点・記号統計：1 文あたりの平均文字数，読点（，・、）の出現頻度，感嘆符や疑問符，括弧類の使用率．
  - 字種構成比：漢字・ひらがな・カタカナの比率．
- **B. 統語・品詞・機能語特徴（トピック非依存の文体特徴）**
  - 品詞 N-gram（POS Bi-gram / Tri-gram）：MeCab の品詞タグ列を用いた文構造パターンの抽出．
  - 機能語（助詞・助動詞・接続詞）の出現頻度：内容語（名詞・動詞・形容詞）を除外し，文末表現（「〜である」「〜だ」「〜た」）や接続表現の癖のみを抽出．
- **C. 語彙・内容特徴（比較用ベースライン）**
  - 単語（内容語を含む）の Bag-of-Words（TF / TF-IDF）：トピックや題材に引きずられるベースラインとしての比較対象．
- **D. 分散表現・潜在意味特徴（講義資料に基づく発展的比較手法）**
  - 第 5 回講義資料の潜在的意味解析（LSI / 特異値分解 SVD）に基づく文書・単語の低次元密ベクトル表現，または第 3 回講義資料の単語分散表現の平均（SIF 重み付け平均等）による意味ベクトル．

### 類似度・距離の算出関数（講義資料登場手法への限定）

> [!IMPORTANT]
> **講義資料（第 2 回・第 3 回・第 5 回）に登場する類似度尺度への限定と条件統制**
> 外部の複雑な指標を排し，講義スライド（第 2 回 p.45，第 3 回 p.25，第 5 回 p.26）で明確に紹介されている**「コサイン類似度（コサイン係数）」「Jaccard 係数」「Dice 係数」の 3 手法**に限定して実装・比較を実施．

| 類似度関数（講義資料準拠） | 数式定義（ベクトル $\vec{x}, \vec{y} \in \mathbb{R}^M$） | 数学的特徴・メリット | デメリット・注意点（A〜D との相性） |
| :--- | :--- | :--- | :--- |
| **1. コサイン類似度**<br>（Cosine Similarity）<br>［第 3 回・第 5 回講義］ | $$\cos(\vec{x}, \vec{y}) = \frac{\sum_{i=1}^M x_i y_i}{\sqrt{\sum_{i=1}^M x_i^2} \sqrt{\sum_{i=1}^M y_i^2}}$$ | ・ベクトルの長さ（文章長）に不変で，向き（構成比）のみを比較<br>・高次元スパース空間や分散表現で最も標準的 | ・**A（N-gram・文体統計）/ B（品詞・機能語）/ C（TF-IDF）/ D（分散表現・LSI）すべてに共通適用可能**な基準尺度<br>・ただし A の「平均文長（例：45.2）と句読点率（例：0.03）」のように**スケールが桁違いの統計量をそのまま入れると平均文長だけで内積が支配される**ため，登録データ（Train）での標準化（Z-score）または L1 正規化が必須 |
| **2. Jaccard 係数**<br>（Jaccard Coefficient）<br>［第 2 回・第 5 回講義］ | ・集合版：$$J(X, Y) = \frac{\|X \cap Y\|}{\|X \cup Y\|}$$<br>・重み付き（実数ベクトル）版：$$J_w(\vec{x}, \vec{y}) = \frac{\sum_{i=1}^M \min(x_i, y_i)}{\sum_{i=1}^M \max(x_i, y_i)}$$ | ・講義資料で「文中の単語の重なり率」および「ベクトル空間モデルの他の類似度係数」として紹介される代表的手法<br>・積 $x_i y_i$ ではなく共通量 $\min(x_i, y_i)$ を評価するため，一部の極端な高頻度語による二乗支配を抑制 | ・非負ベクトル（頻度・比率・TF-IDF）である **A・B・C で有効**<br>・負の値を含む **D（分散表現・LSI）には適用不可**（または 0 以上の要素のみに制限が必要） |
| **3. Dice 係数**<br>（Dice Coefficient）<br>［第 5 回講義］ | ・集合版：$$D(X, Y) = \frac{2 \|X \cap Y\|}{\|X\| + \|Y\|}$$<br>・重み付き（実数ベクトル）版：$$D_w(\vec{x}, \vec{y}) = \frac{2 \sum_{i=1}^M \min(x_i, y_i)}{\sum_{i=1}^M (x_i + y_i)}$$ | ・第 5 回講義（p.26）でコサイン係数・Jaccard 係数と並んで紹介される尺度<br>・共通要素を 2 倍に重み付けし，和で割るため，スパースな特徴でも重なりに対する感度が高い | ・Jaccard と同様，非負の **A・B・C に適用可能**<br>・1 近傍（最大値判定）では Jaccard と順位が一致するが，類似度スコアの絶対値分布や重心・複数近傍平均時に差が生じる |

- **結論（実験方針）**：
  1. **特徴量 A〜D 間の統一比較（メイン実験）**：全特徴量（A〜D）に対して共通に適用できる**コサイン類似度**に固定し，どの特徴量が最も著者識別に有効かを比較．
  2. **類似度計算式の比較（サブ実験）**：非負ベクトルである特徴量 A・B・C において，講義資料の 3 手法（**コサイン類似度 vs Jaccard 係数 vs Dice 係数**）の識別性能と類似度分布の違いを比較．

## 「学習（登録・統計量算出）」フェーズの定義

機械学習（ニューラルネット等）の重み更新ではなく，**「事前登録（Indexing）された各作家の文章群から，特徴量ベクトル化に必要な辞書と基準値を集計・保存するフェーズ」**を指す．具体的には以下の 4 処理のみを実行（評価用 Test 文章は一切混ぜない）：

1. **語彙辞書（Vocabulary）の構築（特徴量 A・B・C・D 共通）**
   - 登録用文章群に出現した全単語・文字 N-gram・品詞 N-gram をリストアップし，「ベクトルの第 $j$ 次元がどの単語（または N-gram）に対応するか」のインデックス対応表（$j = 1, \dots, M$）を固定．
2. **IDF（逆文書頻度）の算出（特徴量 C：TF-IDF 用）**
   - 第 5 回講義（p.13）の数式 $\text{idf}(t) = \log \frac{N}{\text{df}(t)}$ に基づき，登録用チャンク総数 $N$ のうち単語 $t$ が出現するチャンク数 $\text{df}(t)$ を数えて $\text{idf}(t)$ を確定．
3. **スケールの正規化パラメータ算出（特徴量 A：文体統計用）**
   - 「1 文の平均文字数（数十）」と「句読点率（0.0x）」の桁数の違いを揃えるため，登録用データにおける各指標の平均値と標準偏差を算出．
4. **作家の代表ベクトル（または登録ベクトル集合）の保存**
   - 登録用チャンクを上記 1〜3 の基準で数値ベクトルに変換し，重心法用の「作家ごとの平均ベクトル」および $k$-NN 用の「登録チャンクベクトル一覧」としてメモリ（またはファイル）に保持．

（※ 推論・評価フェーズでは，未知のテスト文章を上記 1〜3 で固定したインデックスとパラメータを使って同じ $M$ 次元ベクトルに変換し，4 の登録ベクトルと類似度を計算するのみ．）

  - **太宰治**：『惜別』『斜陽』（小説 2 作品）
  - **寺田寅彦**：『映画芸術』『柿の種』（随筆 2 作品）
  - **田山花袋**：『蒲団』『田舎教師』（小説 2 作品）
- **注意点（サンプルコーパス全体の作品群における文体・表記の性質）**
  - サンプルコーパス全体（30 作品）には，福沢諭吉『学問のすすめ』や幸田露伴『五重塔』などの**文語体・歴史的仮名遣い**作品や，ディケンズ，スウィフト，ツルゲーネフ，ルブランなどの**翻訳文学**が含まれる．
  - これらを混ぜると「作家の文体」ではなく「時代（文語 vs 口語）」「新旧仮名遣い」「翻訳調」の識別になってしまうため，複数作品があり，かつ口語体（言文一致体）で書かれた上記 4 名（漱石・太宰・寅彦・花袋）の選択が最も妥当．
  - **仮名遣いが特徴量に与える影響**：仮名遣いの違い（例：「思ふ」vs「思う」，促音「つ」の大書き等）は，C（単語 TF-IDF）だけでなく，**A（文字 N-gram：直撃）**および **B（品詞・機能語：現代語辞書 MeCab が未知語や誤った品詞に分割する解析エラー）**のすべてに波及．実データをスクリプトで検査し，上記 9 作品の新旧仮名遣いを事前確認することが必須．

### 2. 文境界を考慮したチャンク分割アルゴリズム（Sentence-boundary-aware Chunking）

- **設計方針**：文字数で機械的にスライスすると，文や形態素が途中で切断され，文末表現や 1 文平均文字数，品詞 N-gram が破壊される．そのため，**「文（1 行＝1 文）を最小単位とし，累積文字数が目標閾値 $L \in \{100, 500, 1000\}$ 文字に達した時点の文末で区切る」**グリーディ集約アルゴリズムを採用．
- **端数処理と正規化**：
  - 作品の末尾で閾値 $L$ に満たない端数チャンクは破棄し，チャンク長の極端な偏りを防止．
  - 文単位で区切るため，各チャンクの実際の文字数は $L + \alpha$（$\alpha$ は最後の 1 文の超過分）となるが，特徴量側で**総文字数・総単語数による正規化（相対頻度化）およびコサイン類似度における L2 ノルム正規化**を行うため，微細な文字数差が類似度計算に悪影響を与えることはない．

### 3. 著者判定（推論）アルゴリズムの比較（重心法 vs $k$-NN 法）

| 方式 | アルゴリズム概要 | メリット | デメリット |
| :--- | :--- | :--- | :--- |
| **重心（Centroid）方式** | 各作家 $a$ の登録チャンク群のベクトル平均 $\vec{\mu}_a = \frac{1}{\|D_a\|} \sum_{\vec{v} \in D_a} \vec{v}$ を代表ベクトルとし，入力 $\vec{q}$ との類似度 $\text{sim}(\vec{q}, \vec{\mu}_a)$ を計算（4 回のみ）． | ・計算量が $\mathcal{O}(\|A\|)$ と極めて高速<br>・個々のチャンクの局所的なノイズ（たまたま会話文が多い等）が平均化され，作家全体の「平均的な文体」を安定して表現可能 | ・作家の文体が作品や場面（地の文 vs 会話文，初期作品 vs 後期作品）によって多峰性（複数のクラスタ）を持つ場合，平均ベクトルが実在しない中間点になり精度が低下 |
| **$k$-近傍（$k$-NN）類似度方式** | 入力 $\vec{q}$ と全登録チャンク $\vec{v} \in D_{\text{train}}$ との類似度を全件計算し，各作家 $a$ の登録チャンク群 $D_a$ 内の上位 $k$ チャンクの平均類似度 $\frac{1}{k}\sum_{m=1}^k \text{sim}(\vec{q}, \vec{v}_{a,(m)})$ で判定（Per-Author Top-$k$ 方式をデフォルトとし，全体上位 $k$ 重み付き投票も比較可能）． | ・多峰性の文体（会話主体の場面と描写主体の場面など）に柔軟に対応可能<br>・作家ごとの上位 $k$ 平均をとることで，作家間の作品数・チャンク数の不均衡（漱石 3 作品 vs 他 2 作品）や 4 クラス多数決での同票（タイ）問題を回避可能 | ・登録チャンク数 $\|D_{\text{train}}\|$ に比例して計算量 $\mathcal{O}(\|D_{\text{train}}\|)$ が増加<br>・$k=1$ だと外れ値チャンクに引っ張られ，逆に $k$ を大きくしすぎると重心法（全体平均）に漸近して多峰性が潰れるため，局所〜中域をカバーする $k \in \{1, 3, 5, 10, 20\}$ での感度検証を実施 |

### 4. 技術スタック（`uv` + Python + MeCab）

- **`uv` による環境構築の実現性**：**完全に可能であり，最も推奨される構成**．
- **パッケージ選定（Python 3.13 + `fugashi-plus[unidic-lite]`）**：
  - 従来の `mecab-python3` は OS 側への C++ ライブラリや辞書パスの設定が必要で，班員 4 人の環境（Mac / Windows 混在）で動かなくなるトラブルが多発．また本家 `fugashi` は古い Cython に依存しており Python 3.13 環境や Windows 環境でのビルド問題および型ヒント欠如の課題が存在．
  - 代わりに Python バージョンを **Python 3.13** に固定し，メンテナンスフォークである **`fugashi-plus[unidic-lite]`**（Python 3.13 正式対応・型ヒント同梱のドロップイン代替，コード上は `import fugashi`）を導入すれば，OS 側の設定不要で `uv sync` 一発で全員の環境に同一の MeCab + 辞書環境と IDE 型補完が再現可能．

### システム基盤（リーダー担当）と特徴量モジュール（4 人分担）の分離アーキテクチャ

- **問題点**：構想発表資料のような「前処理担当」「特徴抽出担当」「システム担当」「評価担当」という工程別分業や，「コードを書く人」と「スライドを作る人」の完全分業は，提出プログラムや質疑応答で「プログラミングや実験をしていないメンバー」が露呈し，要件違反となるリスクが極めて高い．
- **解決策（システム基盤はリーダーが構築し，4 人の特徴量モジュールをプラグインとして統合する設計）**：
  - **システム設計・共通パイプライン（リーダー担当）**：
    - コーパス読み込み・文境界チャンク分割（100 / 500 / 1000 文字）・作品内/作品間データ分割器
    - 特徴量抽出器の共通抽象インターフェース（登録データから辞書・統計量を作る `fit` メソッドと，テキスト群を 2 次元配列 `(N_samples, D_features)` に変換する `transform` メソッド）
    - 類似度計算エンジン（コサイン類似度 / Jaccard 係数 / Dice 係数）および推論器（重心法 / $k$-NN 法）・評価パイプライン
  - **特徴量計算モジュールの分担（4 人全員で 1 モジュールずつ担当）**：
    共通インターフェースを継承し，「入力テキスト群を受け取って特徴量の 2 次元配列を返す」計算モジュールのみを 4 人に 1 つずつ割り当てる．これにより，他の班員はシステム全体の複雑なパイプラインを意識せず，自分の特徴量計算ロジックだけに集中でき，かつ全員が明確に「アルゴリズムの実装・実験・考察」に関与した証跡が残る．
    - **担当 A（表層・文体統計モジュール）**：文字 N-gram（Bi-gram / Tri-gram）頻度および句読点率・字種比率・平均文長の抽出と正規化．
    - **担当 B（統語・品詞・機能語モジュール）**：MeCab（`fugashi-plus[unidic-lite]`）を用いた品詞 N-gram（POS Bi-gram）および助詞・助動詞・接続詞（機能語）の相対頻度抽出．
    - **担当 C（語彙・内容 TF-IDF モジュール）**：内容語（名詞・動詞・形容詞）の抽出と，登録データに基づく TF-IDF 重み計算（フルスクラッチ実装）．
    - **担当 D（分散表現・潜在意味モジュール）**：第 5 回講義の特異値分解（SVD / LSI）による低次元文書ベクトル，または第 3 回講義の単語分散表現の平均（SIF 等）によるベクトル算出．
  - **データ確認と結果報告の分担**：各自が自分の担当特徴量モジュール（A〜D）における「作品内分割 vs 作品間分割」「チャンク長変化」の実験結果グラフ・考察スライドを作成し，発表当日も各自のモジュールについて発表．

## 大規模コーパスファイルの取り扱い規約（`llm-context.md` 記載事項）

- **AI エージェントによる直接読み込みの完全禁止**：
  - 解凍された単一コーパスファイル（約 100 万語）を AI エージェントがファイル閲覧ツールや全文出力コマンドで直接読み込むことは，コンテキストウィンドウの枯渇（トークン爆発）やハングアップを引き起こすため**厳禁**とする．
  - データの構造確認（文字コード，作品タイトル行・著者行のフォーマット，新旧仮名遣いの確認など）や抽出処理は，必ず Python 等の文字列処理スクリプト（先頭数十行のみをストリーム処理で読む，あるいは空行区切りを利用してタイトル・著者行のみを抽出して集計する等）を介して実行するルールを `llm-context.md` に明記．
