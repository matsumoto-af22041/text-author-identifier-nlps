# 003: 特徴量 B（品詞 N-gram・付属語）モジュール

## Expected Deliverables & Design Policy

- 担当：メンバー B
- トピックや固有名詞に依存しない統語・文体特徴として， `fugashi` （ `fugashi-plus[unidic-lite]` ）による以下 2 ブロックを結合する `POSFunctionExtractor(BaseFeatureExtractor)` ．
  - **品詞 2-gram 相対頻度**：各形態素の品詞（ `pos1` と `pos2` の組，第 2 回 p.36 の品詞階層）の系列から数えた品詞 2-gram の出現回数 $C(t_{i-1}, t_i)$ （第 2 回 p.30）を，チャンク内の品詞 2-gram 総数で割った相対頻度．
  - **付属語の相対頻度**：第 2 回 p.11 の品詞分類表の付属語（助詞・助動詞）を対象とし，各語の出現回数をチャンクの総形態素数で割った相対頻度（第 5 回 p.12）．助動詞の活用形に現れる文末の癖（「だ」「である」「た」）を保持するため，表層形（ `token_key="surface"` ，第 2 回 p.16）を既定とし，比較用に UniDic の語彙素（ `token_key="lemma"` ，第 2 回 p.16 の原形に相当．未知語で `lemma` が `None` の場合は表層形を用いる）も切り替え可能．
- **対象品詞の切り替え**：既定 `target_pos=["助詞", "助動詞"]` （付属語）．アブレーションとして以下 2 条件を指定可能．
  - 拡張：第 2 回 p.11 で活用のない自立語に分類される接続詞・連体詞・感動詞を加えた `["助詞", "助動詞", "接続詞", "連体詞", "感動詞"]` ．
  - **内容語対照**： `["名詞", "動詞", "形容詞"]` ．付属語ブロックと同じ表現（表層形の相対頻度）・同じ品詞 2-gram ブロックのまま，語の種類だけを内容語に差し替えた統制条件．発表の軸（Core Message）の直接検証に使う．
- **講義資料との関係（発表の軸．本モジュールが主役）**：第 5 回 p.11 では助詞・助動詞は「索引語として不適切な不要語」，p.14-16 では『坊っちゃん』の頻度上位を占める「て・だ・た・は・を」を除くと題材語が残ることを示す．情報検索では内容を表さないため捨てる語を，著者識別では内容に依存しない文体の手がかりとして逆に用いる，という対比を `plans/research-context.md` の Core Message として発表全体の軸に据える．機能語による著者識別の先行研究は Mosteller & Wallace (1964)，金 (2002)，Stamatatos (2009)．
- **『坊っちゃん』頻度表の再現**：講義 p.14 と同じ観点の図表を本コーパスで作るため，作品単位の付属語頻度上位 12 語を出力する関数 `top_function_words(texts, n=12)` を公開（発表スライド用，評価パイプラインでは使用しない）．
- **考察上の要点**：文字表層を見る特徴量 A は底本の漢字・かな表記の揺れに直撃されるのに対し，本モジュールは品詞の並びと付属語のみを見るため表記方針の違いに頑健，という対比を示すこと．

## Target File Paths

- `src/features/pos_function.py`
- `configs/default.yaml` （ `features.B` セクションのみ： `params: {token_key: surface, target_pos: [助詞, 助動詞], max_features: 1500}` ， `ablations: {token_key: [lemma], target_pos: [[助詞, 助動詞, 接続詞, 連体詞, 感動詞], [名詞, 動詞, 形容詞]]}` ）

## Mandatory Constraints

- Comply with `.claude/rules/research-coding.md` (loaded automatically).
- 外部機械学習ライブラリは禁止． `numpy` と `fugashi` のみで実装．
- 総形態素数は補助記号（UniDic の `pos1 == "補助記号"` ）と空白を除いた形態素数（C と同じ定義）．品詞 2-gram は補助記号を含む全形態素の系列から作る（句読点の位置は統語情報のため保持）．
- `target_pos` は次の 3 通りの集合のいずれかと完全一致する場合のみ受け付け，それ以外は `ValueError` ：付属語 `{助詞, 助動詞}` ，拡張 `{助詞, 助動詞, 接続詞, 連体詞, 感動詞}` ，内容語対照 `{名詞, 動詞, 形容詞}` ．付属語と内容語の混在指定は禁止．
- 抽出された語の `pos1` が指定した `target_pos` の範囲内であることを `assert` で検査（既定では名詞・動詞・形容詞・副詞が混入しないこと）．
- `fit` で Train データに出現した品詞 2-gram と付属語の語彙（最小文書頻度 `min_df` 以上，最大 `max_features` 件，既定 1500，同数は辞書順で決定的に選択）を固定し， `transform` では上記の相対頻度（非負）を出力．
- 総形態素数または品詞 2-gram 総数が 0 のテキストは `ValueError` で停止（Fail-Fast）．
- コンストラクタ引数名は `configs/default.yaml` の `features.B.params` / `ablations` （ `token_key` ， `target_pos` ， `max_features` ）と一致させること．
- `BaseFeatureExtractor` は `__init_subclass__` により fit 前 `transform` の停止，出力の 2 次元性・行数一致・有限値，次元数の一貫性， `non_negative = True` 時の非負性を自動検査．

## Verification Criteria

- [ ] 名詞のみを入れ替えた 2 文（「猫は庭で寝ている。」と「犬は庭で寝ている。」）を変換した際，付属語ブロックと品詞 2-gram ブロックがともに一致し，コサイン類似度が $1.0$ （許容誤差 $10^{-9}$ ）．
- [ ] 付属語ブロックの語彙に `pos1` が名詞・動詞・形容詞・副詞の語が含まれないことを，Train に「猫」「走る」「美しい」「ゆっくり」を含むテキストで `assert` 確認．
- [ ] `target_pos=["名詞", "動詞", "形容詞"]` で同じ 2 文を変換した際，語ブロックが一致しない（「猫」「犬」が別次元）ことを確認．
- [ ] `["助詞", "名詞"]` 等の混在指定で `ValueError` ．
- [ ] `top_function_words` を『坊っちゃん』全文に適用した上位 12 語を報告（講義第 5 回 p.14 の上位語「て・だ・た・は・を・の・に・が・と」との重なりを確認．形態素解析器が異なるため完全一致は求めない）．
- [ ] 出力がすべて非負（ `assert np.all(X >= 0)` ）かつ有限値．
