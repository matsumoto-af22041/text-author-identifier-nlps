# Ticket 3: 【担当 B】統語・品詞 N-gram・機能語モジュールの実装（担当：メンバー B）

## 1. 期待される成果物と設計方針（Expected Deliverables & Design Policy）

- 作品の題材（トピックや固有名詞）に依存しない純粋な統語・文体特徴として，`fugashi-plus[unidic-lite]`（コード上は `import fugashi`）を用いた以下の特徴量を抽出する `POSFunctionExtractor(BaseFeatureExtractor)` の実装：
  1. **品詞 N-gram（POS Bi-gram / Tri-gram）相対頻度**：各形態素の品詞大分類（`pos1`）および品詞中分類（`pos2`）の系列から構築した品詞遷移パターンの相対頻度（例：「名詞→助詞」「助動詞→補助記号」など）．
  2. **機能語（Function Words）の相対頻度（確定仕様）**：内容語（名詞・動詞・形容詞・副詞）を除外し，**助詞・助動詞・接続詞・連体詞・感動詞（および文末の補助記号）** のみを対象とする．助動詞（「だ」「である」「た」等）の活用形に現れる文末の文体的特徴を保持するため，**形態素の表層形（`token_key="surface"`）＋品詞をデフォルト（本採用）** とし，質疑応答での比較検証用に語彙素・基本形（`token_key="lemma"`）も引数で切り替え可能とすること．

## 2. 対象ファイルパス（Target File Paths）

- `src/features/pos_function.py`

## 3. 必須制約事項（Mandatory Constraints）

- 作業開始前に必ずプロジェクトルートの `llm-rules.md` および `llm-context.md` を精読し，すべての規約を遵守すること．
- `scikit-learn` 等の外部機械学習ライブラリの使用は一切禁止．`numpy` と `fugashi-plus[unidic-lite]`（`import fugashi`）のみを用いて実装すること．
- 固有名詞や一般名詞（「山嵐」「先生」「斜陽」等），動詞・形容詞・副詞が絶対に機能語語彙に混入しないよう，対象品詞タプル `TARGET_POS1 = ("助詞", "助動詞", "接続詞", "連体詞", "感動詞", "補助記号")` を厳密に定義すること．
- `fit(train_texts)` で Train データに出現した品詞 N-gram および機能語の語彙辞書（最小出現文書頻度 `min_df` 以上，かつ計算量抑制のため **最大次元数上限 `max_features=1500` 以内**）を固定し，`transform(texts)` では各チャンクの総形態素数で割った相対頻度（非負ベクトル）を出力すること．
- **発表・考察時の重要ポイント**：担当 A（文字表層）は作品ごとの底本の漢字・かな表記の揺れ（例：「大分」vs「だいぶ」）に直撃されるのに対し，本モジュールは内容語や漢字表記に依存しない「品詞の並びと機能語」のみを見るため，底本の表記方針の違いに対して頑健であることをアピールすること．

## 4. 完了検証基準（Verification Criteria）

- 同じ文構造で名詞だけを入れ替えた 2 つのダミー文（例：「吾輩は猫である。」と「先生は人間である。」）を変換した際，名詞の違いに影響されず機能語（「は」「である」「。」）と品詞系列が一致し，高いコサイン類似度（$> 0.8$）を示すことを確認すること．
- 出力行列がすべて非負（`assert np.all(X >= 0)`）かつ有限値であることを確認すること．
