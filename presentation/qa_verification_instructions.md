# 発表・質疑応答対策ドキュメント作成および検証タスク指示書（Ticket QA-1）

## 概要と目的

最終発表および質疑応答において，担当教員や聴講者から実験設計の妥当性・ハイパーパラメータの選定根拠・交絡因子の有無について鋭い指摘（ツッコミ）が入ることが予想される．本ドキュメントは，想定される質問項目を網羅的に洗い出し，**設計段階で確定させた「本採用仕様（デフォルト方針）」と「対照実験フラグ（アブレーション設定）」**を明示した上で，発表用防衛資料を構築するための実装・文書化指示書である．

---

## 1. 期待される成果物と設計方針（Expected Deliverables & Design Policy）

以下の 3 つの観点を体系的に整理した発表・質疑応答対策マスタードキュメント（`presentation/qa_defense_matrix.md`）を作成し，必要な追加検証スクリプトまたは集計処理を実装・実行して定量的根拠を埋めること．

### 観点 A：データセット・前処理・辞書選定に関する質問（交絡因子とデータ漏洩への防御）

| 想定質問・ツッコミ項目 | 確定済みの設計方針（本採用仕様） | 追加検証の要否 | 回答ロジック・必要な検証データ |
| :--- | :--- | :---: | :--- |
| **Q1. なぜ 30 作品あるのに 4 作家（9 作品）しか使わないのか？** | **4 作家（漱石 3・太宰 2・寅彦 2・花袋 2）の計 9 作品に完全固定**． | **要検証（Ticket 0 で集計）** | ・「未知作品に対する著者識別（Inter-work Split）」を行うには，1 作家あたり最低 2 作品以上が必須．<br>・コーパス内全 30 作品を作家別に集計した結果，複数作品を持つ作家がこの 4 名のみである事実を一覧表で提示．<br>・さらに他作品には文語体（福沢諭吉・幸田露伴）や翻訳文学（ディケンズ等）が含まれ，混ぜると「文体」ではなく「時代・翻訳調」の識別になる（交絡因子）ため除外したと説明． |
| **Q2. フル版 `unidic` や近代文語 UniDic ではなく `unidic-lite` を使った弊害はないのか？** | **Python 3.13 + `fugashi-plus[unidic-lite]` を採用**．<br>・担当 C（内容語）は表記揺れ吸収のため `lemma`（語彙素）を固定採用．<br>・担当 B（機能語）は文末活用形保持のため `surface`（表層形）をデフォルト採用． | **要検証（Ticket 0 で確認）** | ・新語削除と属性削減（29→17 個）が無害である理由，および語種 `goshu` 欠落を担当 A の字種比率で代替している点は `presentation/note.md` の通り．<br>・実データ検査として，対象 9 作品の仮名遣い（新字新仮名か否か）と，表記揺れ（「矢張」と「やはり」等）が `lemma`（語彙素）で同一化できている具体例を 2〜3 個抽出して提示． |
| **Q3. チャンク分割で「目標文字数 $L$ に達した文末で区切る」と，チャンク間で文字数にバラつきが出て不公平では？** | **文境界保持グリーディ分割（$L \in \{100, 500, 1000\}$）＋相対頻度化＋L2 正規化**で完全確定． | **検証不要（仕様説明＋基本統計）** | ・文の途中で切ると文末表現（助動詞・終助詞）や品詞 N-gram が破壊されるため，文境界保持は必須．<br>・文字数差 $\alpha$ の影響は，①特徴量側での相対頻度化（総文字数・総形態素数での除算）および②コサイン類似度の L2 ノルム正規化により完全にキャンセルされる．念のため実際のチャンク長分布（平均±標準偏差）のみ算出して控えスライドに載せる． |
| **Q4. 作品の末尾の端数チャンクを捨てているが，作品の結論部分（結びの文体）を捨てるバイアスにならないか？** | **作品末尾の $L$ 文字未満の端数チャンクは破棄**で確定． | **検証不要（仕様説明）** | ・1 作品あたり数万文字ある中で，末尾の $L$ 文字未満（数百文字）は全体の 1% 未満．<br>・逆に極端に短い端数チャンクを残すと，スパース性が高まりゼロベクトルや極端な外れ値を生むため，除外する方が統計的に健全である． |

### 観点 B：特徴量設計・ハイパーパラメータに関する質問（アブレーションと感度分析）

| 想定質問・ツッコミ項目 | 確定済みの設計方針（本採用仕様） | 追加検証の要否 | 回答ロジック・必要な検証データ |
| :--- | :--- | :---: | :--- |
| **Q5. なぜ「同一作品内分割（Intra-work）」と「作品間分割（Inter-work）」の両方を比較するのか？** | **両分割方式を実装し，Inter-work（Leave-One-Work-Out）を主評価指標**に確定． | **要検証（メイン実験）** | ・Intra-work では同じ作品の別チャンクが Train と Test に入るため，登場人物名（「山嵐」「先生」等）や題材の一致（トピック漏洩）だけで内容語 TF-IDF（担当 C）が高精度を出してしまう．<br>・Inter-work（未知作品テスト）で TF-IDF の精度が急落し，文体特徴（担当 A・B）が高精度を維持することを示すのが本研究の最大の貢献である． |
| **Q6. 担当 A で「平均文長」と「文字 N-gram 頻度」をそのまま結合すると，平均文長（数十）のスケールが大きすぎてコサイン類似度が支配されないか？** | **Train データでの Min-Max 正規化（$[0, 1]$ 非負スケーリング）をデフォルト（本採用）** に確定．<br>（引数 `scaling="minmax" \| "zscore" \| "none"` で切り替え可能に設計） | **要検証（アブレーション）** | ・未正規化（`"none"`）のまま結合すると平均文長 1 次元だけでコサイン類似度がほぼ決まってしまう．<br>・また Z-score 標準化は負の値が生じるため Jaccard / Dice 係数に適用できない．よって $[0, 1]$ の Min-Max 正規化をデフォルトとし，`scaling="none"` と比較して精度が劇的に改善する数値を提示する． |
| **Q7. 担当 B の機能語抽出で，なぜ動詞や副詞を入れないのか？また `surface`（表層形）と `lemma`（基本形）のどちらを使ったのか？** | ・対象品詞は **助詞・助動詞・接続詞・連体詞・感動詞・補助記号** に固定．<br>・特徴量キーは **表層形（`token_key="surface"`）をデフォルト（本採用）** に確定（`"lemma"` も切り替え可能）． | **要検証（アブレーション）** | ・動詞・形容詞・副詞を入れると作品の行動・題材（トピック）が混入するため除外．<br>・助動詞（「だ」「である」「た」「ない」）は活用形の違い自体が文体（「〜である。」vs「〜だ。」）を表すため，`lemma` で原形に戻すと文末の癖が消える．`surface` と `lemma` の精度を比較し，`surface` 採用の妥当性を定量的に示す． |
| **Q8. 担当 C（TF-IDF）の IDF 計算式で，$\log(N/\text{df})$ なのか $\log(N/\text{df}) + 1$ なのか？テストデータの単語はどう扱ったか？** | ・**平滑化付き $\text{idf}(t) = \log(N/\text{df}(t)) + 1$ をデフォルト**に確定（`smooth_idf=False` も選択可能）．<br>・特徴量キーは **`lemma`（語彙素）に固定**． | **検証不要（数式・実装説明）** | ・第 5 回講義スライドの定義と，全チャンク出現語（$\text{df}=N$）が 0 になるのを防ぐ `+1` 平滑化の違いを説明．<br>・DF および語彙辞書は **Train データのみ**から構築し，Test のみの未知語（OOV）は無視することで情報漏洩とゼロ除算を完全に防いでいることをコード構造とともに説明． |
| **Q9. 担当 D（LSI / SVD）の圧縮次元数 $K$ はどうやって決めたのか？なぜ Jaccard / Dice を使わないのか？** | ・類似度関数は **コサイン類似度のみに固定**．<br>・デフォルト次元数は **$K = 32$** に確定し，$K \in \{8, 16, 32, 64\}$ を比較． | **要検証（次元数 $K$ の推移）** | ・特異値分解 $X = U \Sigma V^T$ により得られる右特異ベクトル $V_K$ には負の成分が含まれるため，非負ベクトルを前提とする Jaccard / Dice 係数（$\min, \max$ 演算）は数学的に適用不可．<br>・次元数 $K \in \{8, 16, 32, 64\}$ を変化させた際の累積寄与率（特異値の二乗和比率）と識別精度の推移を検証して最適値を提示． |

### 観点 C：類似度関数・推論方式・評価指標に関する質問（数学的性質と誤分類分析）

| 想定質問・ツッコミ項目 | 確定済みの設計方針（本採用仕様） | 追加検証の要否 | 回答ロジック・必要な検証データ |
| :--- | :--- | :---: | :--- |
| **Q10. Jaccard 係数と Dice 係数は，1-NN（最も類似度が高い 1 チャンクで判定）のとき結果が完全に一致するのではないか？** | **数学的に完全一致することを前提として設計**し，類似度関数の比較実験では必ず **$k \ge 3$ の $k$-NN（上位 $k$ 平均）を含める** 方針に確定． | **要検証（理論説明＋実験確認）** | ・**数学的事実**：任意の 2 ベクトル間で $D(\vec{x}, \vec{y}) = \frac{2 J(\vec{x}, \vec{y})}{1 + J(\vec{x}, \vec{y})}$ が成り立ち，$J$ に関して厳密に単調増加であるため，**重心法や $k=1$ の $k$-NN 法では，Jaccard と Dice の予測ラベル（Accuracy）は 100% 数学的に一致する**．<br>・差が出るのは「$k \ge 3$ の $k$-NN 法で上位 $k$ 個の類似度の**平均**をとる場合（非線形変換により平均の大小関係が逆転しうる）」および「類似度分布のヒストグラム形状」のみ．この数学的性質を発表内で先回りして言及する． |
| **Q11. 重心法（Centroid）と $k$-NN 法のどちらが良かったか？またなぜ $k \in \{1, 3, 5, 10, 20\}$ で「作家別上位 $k$ 平均（Per-Author Top-$k$）」なのか？** | ・**`knn_mode="per_author"`（各作家の登録チャンク内の上位 $k$ 個の平均類似度）をデフォルト**に確定（`"global"` も切り替え可能）．<br>・検証レンジは **$k \in \{1, 3, 5, 10, 20\}$** に確定． | **要検証（実験比較）** | ・**なぜ奇数（1, 3, 5）だけの多数決ではないのか**：4 クラス分類では $k=3$ でも $(1,1,1,0)$，$k=5$ でも $(2,2,1,0)$ の同票（タイ）が生じる．また全体から上位 $k$ 個を取る方式（Global Top-$k$）は，作品数が多く登録チャンク数が多い夏目漱石（3 作品）が有利になるクラス不均衡バイアスを持つ．<br>・**なぜ Per-Author Top-$k$ で $10, 20$ まで見るのか**：作家ごとに上位 $k$ 個の平均類似度をとればチャンク数不均衡と同票問題を同時に解消でき，$k=1$（局所 1-NN と一致）から $k=3, 5$（局所場面マッチング），$k=10, 20 \to \text{Centroid}$（大域平均への漸近）までの多峰性の影響を連続的に評価できる． |
| **Q12. どの作家とどの作家が一番間違えやすかったか（混同行列の傾向）？また何文字（$L=100, 500, 1000$）あれば十分判定できるか？** | **チャンク長 $L \in \{100, 500, 1000\}$ の精度推移グラフと混同行列の出力**で確定． | **要検証（混同行列・エラー事例抽出）** | ・混同行列（Confusion Matrix）を提示し，たとえば自然主義の田山花袋と他作家の混同や，$L=100$（短文）で誤分類された具体的なチャンクのテキスト例（例：短い会話文だけで地の文がないチャンク等）を 1〜2 件抜粋して定性考察を行う． |

## 3. 必須制約事項（Mandatory Constraints）

1. 作業開始前に必ずプロジェクトルートの `llm-rules.md` および `llm-context.md` を精読し，すべての規約を厳守すること．
2. **巨大コーパスファイルの直接読み込み禁止**：`data/raw/corpus20150426_with_titles.txt` を AI エージェントのファイル閲覧ツールで直接開くことは絶対に行わないこと．必ず Python スクリプトの行単位ストリーム処理を介して検査すること．
3. **禁止ライブラリの厳守**：`scikit-learn` 等は一切使用せず，Python 3.13 環境下で `numpy` と `fugashi-plus[unidic-lite]`（インポート名は `fugashi`）のみを使用すること．
4. ドキュメントの記述スタイルは，プロジェクトのドキュメント規約（体言止め，全角カンマ・ピリオド `，．`，半角英数字・数式前後の半角スペース挿入）に厳密に従うこと．

## 4. 完了検証基準（Verification Criteria）

1. **Q10（Jaccard vs Dice の数学的性質）の数値検証**：
   - ランダムな非負行列または実データ特徴量において，重心法および $k=1$ の $k$-NN 法を実行した際，Jaccard 係数と Dice 係数の予測ラベル配列が全サンプルで完全に一致すること（`assert np.array_equal(pred_jaccard_1nn, pred_dice_1nn)`）を確認し，その理論的理由（$D = \frac{2J}{1+J}$ の単調性）が `presentation/qa_defense_matrix.md` に明記されていること．
2. **Q1・Q2・Q3 のコーパス・辞書実態データの記載**：
   - `uv run python scripts/verify_qa_points.py` を実行し，対象 4 作家・9 作品の文字数・文数，チャンク分割後の実測文字数（平均・標準偏差），および `unidic-lite` による機能語・表記揺れ解析の具体例が出力され，`presentation/qa_defense_matrix.md` に定量値として反映されていること．
3. **アブレーション設定と実験結果の紐付け**：
   - 各想定質問に対して「どのデフォルト仕様で本実験を回し，どの切り替えフラグ（`scaling`, `token_key`, `knn_mode`, $k \in \{1, 3, 5, 10, 20\}$, $K \in \{8, 16, 32, 64\}$）で対照実験の数値を出したか」が班員全員に一目で分かる形式で整理されていること．
