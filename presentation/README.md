# スライド作成の手引き

スライド作成担当（研究の経緯を知らない班員）が最初に読む案内．内容は既存の資料の要約と案内のみで，新しい数値や主張は含まない．

## 使う資料

- `presentation_storyline.md` ：スライドごとの載せるデータ・主張・数値・出典・想定時間の設計図．スライドの構成はこのファイルに従う（2026-11-24 に組み替え．041 で表紙・指標の定義・基準値の根拠を追加，042 で発表の要件に合わせシステムの機能・使用したツール・参考文献を追加し，統制比較と類似度ギャップを補助に移して番号を振り直し．041 の版の番号との対応は末尾の「041 の版との対応表」，039 の版との対応は「039 の版との対応表」，旧構成との対応は「旧構成との対応表」）．
- `qa_defense_matrix.md` ：想定質問と回答，数値（run 名付き）と出典の一覧．
- `slides_d.md` ：担当 D（LSI）のスライド案．
- `figures/` ：発表に使う図（日本語表記， `full_006` から再生成，031．基準値の線と凡例の位置は 035）．

## 使わない資料

- `qa_verification_instructions.md` ：2026-11-18 時点の旧値．数値を写さない（最新の数値は `qa_defense_matrix.md` ）．
- `note.md` ：形態素解析辞書の選定の背景資料．結果の数値は含まない．

## 数値の写し方

- 数値は `presentation_storyline.md` と `qa_defense_matrix.md` から，出典の run 名ごと写す．数値を自分で計算・丸め直ししない．
- 使う run 名： `full_006` （本実験）， `sensitivity_029_L{100,500,1000}` （語彙選択に対する感度． `outputs/` の `sensitivity_029_L*_clean` はコミット後の再実行で，CSV は同一）， `function_word_profiles` （作家ごとに偏りのある付属語），その他 storyline の「数値の出典と書き方」に載っている run．
- `outputs/` を直接見る場合も run 名を併記．
- 古い run（ `c_only` ， `base_c_022` 等）の数値は使わない．

## 発表スライドの生成

- 発表スライドは `slides.pptx` の 1 ファイル．修正は生成スクリプト（ `scripts/build_slides.py` ）と内容のデータ（ `slides_content.yaml` ）で行い，pptx を直接編集しない（039）．
- 内容は storyline の各スライドの「載せるデータ・主張・出典」の要約．新しい数値・主張は加えない．配色・フォント・縦横比は元のスライドのテーマから読み取った値（ `slides_content.yaml` の `theme` ）．
- 再現コマンド：

```sh
uv run python scripts/plot_slide_figures.py   # グラフ A・B-1・C・F，図 B・グラフ E と補助 S16 のスライド用の再描画，Test の作家構成の図を full_006 から描画
uv run python scripts/build_slides.py         # slides.pptx を生成（数式の画像化にローカルの TeX が必要．下記）
uv run python scripts/check_slides.py         # 構成・数値・数式・書き方・個人名・はみ出しの検査（違反があれば終了コード 1）
```

- ビルドにはローカルの TeX（ `lualatex` ， `standalone` ・ `amsmath` ）と Poppler の `pdftocairo` が必要．コマンドは PATH から探し，無ければ `--lualatex` ・ `--pdftocairo` で指定（既定は `slides_content.yaml` の `theme.math` ）．見つからない・コンパイルに失敗した場合は停止．数式の PNG は `outputs/slides_math/` にキャッシュ（Git 管理外，pptx に埋め込まれるため PNG はコミットしない）．
- `check_slides.py` の検査の基準はスクリプト冒頭に記載．数値は，`slides_content.yaml` の表の `refs` とスライドの `num_refs` で対応付けたものを指標・条件（特徴量， $L$ ，分割，間引き，推論方式）まで出典の CSV・storyline の表のセルと照合し，対応付けのない数値は `num_sources` で指定した storyline・qa・slides_d の範囲とトークン単位で照合（040）．

## 用語と出典

- 指標名は「作家別 MAP の平均」「作家別正解率の平均」「作家別 F 値の平均」．Balanced Accuracy，マクロ F1，（単独の）正解率は使わない．
- 外部文献は引用しない．出典は講義資料の回・頁（例：第 5 回 p.13）か「独自設計」．

## スライドの書き方

研究者の指定（2026-11-24）．

- スライド内の文章は短く．1 スライドの主張は 1 つ．
- 要素の列挙は読点で区切らず箇条書き．
- 記号・用語の定義は，発表全体で使うものを Slide 4（記号・用語）と Slide 5（指標の定義と基準値）に，パートごとに使うものを各パートの最初のスライドにまとめる．後のスライドで定義する語には「（後述）」を付ける．
- A～D に共通の実験条件（分割， $L$ ，推論方式，間引き）は Slide 8 に 1 か所だけ書き，各パートの実験の概要には固有の条件だけを書く．
- 本編のチャンク長は $L = 500$ に固定し，他の $L$ は補助 S7 にのみ書く（042）．本編の指標は作家別 MAP の平均と作家別正解率の平均の 2 つ（2 つに絞った理由は補助 S4，作家別 F 値の平均・MRR の定義と基準値は補助 S5． $\Delta S$ は 045 で発表から外した）．補助スライドも同じ 2 つの指標だけを使う（044．例外は補助 S4・S5・S17 で，内容データに `extra_metrics: true` ）．
- 本編の本文に補助スライドの番号（「補助 S9」等）を書かない．補足が必要な箇所は余白に簡潔な説明を書く（044．発表者ノートには書いてよい）．
- 各担当の定義のスライドには，コサイン類似度で比べるベクトル（Test チャンクのベクトルと各作家の重心，同じ空間）を書く（042）．
- 「アブレーション」は使わず，「既定と比べる条件」「構成要素を外した比較」等の平易な言い方にする．
- 出典は文中に書かない．該当箇所の右肩に [1] 等の番号を付け，スライド下部に薄い文字で表示．
- 出典にプログラム名・スクリプト名・run 名を書かない（講義資料の回・頁，または「独自設計」）．run 名は発表者ノートや storyline でのみ扱う．
- A～D の各担当は 定義 / 実験の概要 / 結果・考察 の 3 枚．
- 各スライドの想定時間は storyline の「想定時間」に従う（発表の要件は 15～20 分．本編 24 枚で計 18 分 30 秒，042）．
- 1 枚目は表紙（タイトル，班の氏名欄のプレースホルダ．科目名の副題は 045 で削除）．本編の最後（結論の後，補助スライドの前）は参考文献（講義資料の各回・頁，構想発表資料，コーパスの説明資料．チケット番号・プログラム名・個人名は書かない，042）．参考文献のスライドは文献の一覧だけにし，方針の記述と主張の帯を置かない（044）．各スライド下部の出典もそのまま．
- 発表の要件（第 6 回 p.48-49：実験の目的，システムの機能，アルゴリズムの説明，使用したデータ，使用したツール，実験結果，考察，分担，参考文献）とスライドの対応は storyline の「スライド構成」の節．
- 質疑用の補助スライド（S1～S17，045）は参考文献の後ろに置く．補助スライドは聴衆の質問への反論の材料で，「質問 → 答え → 根拠の数値・図」の形にそろえる（042，044）：`question` に質問の文だけ（題名の直下に表示．「想定質問：」「答え：」の文字列と質問の番号はスライドに出さない），`claim` に答え（主張の帯），本文に根拠．`qa` に `qa_defense_matrix.md` の質問の番号（追加質問は見出し名），`supplements` に対応する本編のスライドの番号を書き，どちらも発表者ノートにのみ出す．補助スライドは `supplements` の昇順（同じ本編のスライドに対応するものは関連の強い順）に並べる（044，並べ方の基準は storyline の「補助スライド」の節）．補助スライドには「事前の仮説」「仮説は支持されない」等の記述と本編で扱わない結論を書かず，未検証の説明は「（未検証）」と書く．本編の結論に補助スライドだけを根拠とする記述を書かない．主張の帯はその質問への直接の答えにし，本文は答えの根拠だけで構成する（質問と関係のない表・数値は載せない，045）． $\Delta S$ は本編・補助スライドとも扱わない（045）．
- 数式は `slides_content.yaml` の文字列中に `$...$` （LaTeX の記法）で書く（040）．ビルドで 1 式ずつ TeX でコンパイルした画像（Computer Modern，代替テキストに元の LaTeX）としてスライドに置く．短い記号（1 文字の変数，添字のない記号，`\text{...}` ，数値と演算子．例： `$L = 500$` ， `$K$` ， `$\Delta S$` ）も画像にし，書体を Computer Modern にそろえる（041）．本文・表のセル（見出しを含む）・定義の一覧・主張の帯・強調枠・図形の中のどこにでも書ける．`_{x}` ・ `^{x}` の独自記法や `‖` ・ `Σ` 等を平文で並べた式は使わない．
  - PowerPoint 上で式を編集しない（画像のため）．修正は yaml とスクリプトで行う．
  - 画像の数式は文中にも置けるが，段落の途中の複雑な式（分数・総和等，または添字・上付き・ノルムを含む等式・関数の形・割り算）は避け，数式だけの段落（独立の行）に出す．該当する式はビルドの出力に一覧される（041 の時点で 0 個）．
  - 表のセル内の数式も画像にする．セルの文字は上下中央ぞろえのため，画像はセルの余白の内側の領域で段落の高さの合計から求めた上下中央の行に，左ぞろえの行頭からの位置で置く（右ぞろえの数値のセルには数式を書かない）．
  - 発表者ノートは平文のまま（数式の記法を使わない）．
- 「用語：説明」の形の定義の並びは `deflist` ブロック（罫線なしの 2 列の表．左列：用語・記号，右列：説明）で書き，各列の行頭をそろえる（040）．定義の一覧は「用語：定義」の行だけにし，それ以外の説明文（「値はすべて～」等）は一覧の下に箇条書きで並べる（042， `check_slides.py` で検査）．

## 個人名・秘匿情報の扱い

- **個人名・学籍番号など秘匿すべき文字は，スライドに限らずリポジトリ内のすべてのファイル（スライド，Markdown，図，コード，コミットメッセージ）に入れない**．
- 氏名は「担当 A」～「担当 D」「リーダー」と書き，提出直前に研究者が記入．
- 担当の割り当て（ `plans/` ・ `presentation/` の記載）は従来どおり．実際のスライド作成は研究者．
- 担当から上がった元のスライド（ `presentation/orig.*` ）は個人名を含むため Git 管理外．
- 発表スライドは `presentation/` に 1 ファイルのみ置き，Git で版を管理．
- 提出直前に氏名を書き込んだ版（ `*_提出用.*` ）と PDF は Git 管理外（ `.gitignore` ）．
- 図の中の文字（凡例・注記）やファイル名，発表者ノートも対象．

## 主張の線（言い過ぎないための注意）

結論の書き方は `plans/research-context.md` の「発表の軸」（2026-11-24 再改訂）と storyline の Slide 23 に従う．要点は次のとおり．

- 発表の軸は「4 つの観点（A～D）で類似度を測り，未知作品の著者を識別できるのはどれか，できないならなぜか」．
- 本編の「なぜか」は作品内分割と作品間分割の差（トピック漏洩，Slide 22）で示す．研究の仮説は Slide 2 に示し，全体比較（Slide 21）と結論（Slide 23）はそれを参照する．
- 旧 Core Message（「情報検索では捨てる語が，著者識別では手がかりになる」）は発表の主題ではなく，B の付属語と内容語の統制比較（補助 S11，本編・結論には書かない）の位置付け．判別（作家別正解率の平均）では支持．同一著者の文章を上位に並べる力（作家別 MAP の平均）では，作品固有の語を除いた内容語とほぼ同等．
- 「B が最良」とは言わない．未知作品で最も高いのは A，作品が変わって最も落ちにくいのは B．
- 寺田寅彦の 2 作品は統制比較の例外として，質疑で補助 S13 を示す．
- 最良モデルの値は Test で選んだ楽観的な上限．
- 付属語の具体例（表 B-3，補助 S14）は記述統計．作家の癖か作品の語りの様式かは区別できない．
- 仮説と確認済みの事実を区別する（storyline の「仮説」の表記を落とさない．スライドの補助では「（未検証）」と書く）．

## 質問の窓口

分からない数値・主張はリーダーに確認．
