# スライド作成の手引き

スライド作成担当（研究の経緯を知らない班員）が最初に読む案内．内容は既存の資料の要約と案内のみで，新しい数値や主張は含まない．

## 使う資料

- `presentation_storyline.md` ：スライドごとの載せるデータ・主張・数値・出典・想定時間の設計図．スライドの構成はこのファイルに従う（2026-11-24 に組み替え．旧構成のスライド番号との対応は末尾の「旧構成との対応表」）．
- `qa_defense_matrix.md` ：想定質問と回答，数値（run 名付き）と出典の一覧．
- `slides_d.md` ：担当 D（LSI）のスライド案．
- `figures/` ：発表に使う図（日本語表記， `full_006` から再生成，031．基準値の線と凡例の位置は 035）．

## 使わない資料

- `qa_verification_instructions.md` ：2026-11-18 時点の旧値．数値を写さない（最新の数値は `qa_defense_matrix.md` ）．
- `note.md` ：形態素解析辞書の選定の背景資料．結果の数値は含まない．

## 数値の写し方

- 数値は `presentation_storyline.md` と `qa_defense_matrix.md` から，出典の run 名ごと写す．数値を自分で計算・丸め直ししない．
- 使う run 名： `full_006` （本実験）， `sensitivity_029_L{100,500,1000}` （語彙選択に対する感度． `outputs/` の `sensitivity_029_L*_clean` はコミット後の再実行で，CSV は同一）， `function_word_profiles` （作家ごとに偏りのある付属語），その他 storyline の「数値の出典と書き方」に載っている run．
- `outputs/` を直接見る場合も run 名を併記．
- 古い run（ `c_only` ， `base_c_022` 等）の数値は使わない．

## 発表スライドの生成

- 発表スライドは `slides.pptx` の 1 ファイル．修正は生成スクリプト（ `scripts/build_slides.py` ）と内容のデータ（ `slides_content.yaml` ）で行い，pptx を直接編集しない（039）．
- 内容は storyline の各スライドの「載せるデータ・主張・出典」の要約．新しい数値・主張は加えない．配色・フォント・縦横比は元のスライドのテーマから読み取った値（ `slides_content.yaml` の `theme` ）．
- 再現コマンド：

```sh
uv run python scripts/plot_slide_figures.py   # グラフ A・C・F（figures/a_ablation.png，c_intra_inter.png，classifier_comparison.png）を full_006 から描画
uv run python scripts/build_slides.py         # slides.pptx を生成
uv run python scripts/check_slides.py         # 構成・数値・書き方・個人名・はみ出しの検査（違反があれば終了コード 1）
```

- `check_slides.py` の検査の基準はスクリプト冒頭に記載．数値は `slides_content.yaml` の `num_sources` で指定した storyline・qa・slides_d の範囲と照合．

## 図

- `figures/` の図を使う．
- `chunk_length_curves.png` ・ `core_chunk_length.png` の凡例は図の下にまとめて表示（035）．
- `chunk_length_curves.png` の作家別 MAP の平均のパネルの黒の細線（印なし）は基準値（実線：間引きあり，破線：間引きなし）．基準値は間引きの有無で異なる（ $L = 500$ の Inter-work で 0.260 / 0.157）ため，間引きあり・なしの比較は基準値との差で見る（035）．

## 用語と出典

- 指標名は「作家別 MAP の平均」「作家別正解率の平均」「作家別 F 値の平均」．Balanced Accuracy，マクロ F1，（単独の）正解率は使わない．
- 外部文献は引用しない．出典は講義資料の回・頁（例：第 5 回 p.13）か「独自設計」．

## スライドの書き方

研究者の指定（2026-11-24）．

- スライド内の文章は短く．1 スライドの主張は 1 つ．
- 要素の列挙は読点で区切らず箇条書き．
- 記号・用語の定義は，発表全体で使うものをスライド 2 に，パートごとに使うものを各パートの最初のスライドにまとめる．
- 出典は文中に書かない．該当箇所の右肩に [1] 等の番号を付け，スライド下部に薄い文字で表示．
- 出典にプログラム名・スクリプト名・run 名を書かない（講義資料の回・頁，または「独自設計」）．run 名は発表者ノートや storyline でのみ扱う．
- A～D の各担当は 定義 / 実験の概要 / 結果・考察 の 3 枚．
- 各スライドの想定時間は storyline の「想定時間」に従う（本編は 20 枚程度で計 20 分程度）．
- 質疑用の補助スライド（S1～S14）は結論・出典一覧の後ろに置き，対応する想定質問の番号を書く．

## 個人名・秘匿情報の扱い

- **個人名・学籍番号など秘匿すべき文字は，スライドに限らずリポジトリ内のすべてのファイル（スライド，Markdown，図，コード，コミットメッセージ）に入れない**．
- 氏名は「担当 A」～「担当 D」「リーダー」と書き，提出直前に研究者が記入．
- 担当の割り当て（ `plans/` ・ `presentation/` の記載）は従来どおり．実際のスライド作成は研究者．
- 担当から上がった元のスライド（ `presentation/orig.*` ）は個人名を含むため Git 管理外．
- 発表スライドは `presentation/` に 1 ファイルのみ置き，Git で版を管理．
- 提出直前に氏名を書き込んだ版（ `*_提出用.*` ）と PDF は Git 管理外（ `.gitignore` ）．
- 図の中の文字（凡例・注記）やファイル名，発表者ノートも対象．

## 主張の線（言い過ぎないための注意）

結論の書き方は `plans/research-context.md` の「発表の軸」と storyline の Slide 21 に従う．要点は次のとおり．

- 発表の軸は「4 つの観点（A～D）で類似度を測り，未知作品の著者を識別できるのはどれか，できないならなぜか」．
- 旧 Core Message（「情報検索では捨てる語が，著者識別では手がかりになる」）は発表の主題ではなく，B の付属語と内容語の統制比較（Slide 20）の位置付け．判別（作家別正解率の平均）では支持．同一著者の文章を上位に並べる力（作家別 MAP の平均）では，作品固有の語を除いた内容語とほぼ同等．
- 「B が最良」とは言わない．未知作品で最も高いのは A，作品が変わって最も落ちにくいのは B．
- 寺田寅彦の 2 作品は例外として必ず示す．
- 最良モデルの値は Test で選んだ楽観的な上限．
- 付属語の具体例（表 B-3，補助 S3）は記述統計．作家の癖か作品の語りの様式かは区別できない．
- 仮説と確認済みの事実を区別する（storyline の「仮説」の表記を落とさない）．
